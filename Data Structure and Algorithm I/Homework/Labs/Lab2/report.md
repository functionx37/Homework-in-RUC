## 实验报告 

#### 实验名称  
航线图构造与航线规划系统设计  

#### 代码实现

##### 数据结构

- **Flight 结构体**: 存储航班的详细信息，包括航班号、起降机场、起降时间、票价等。为了方便计算，起降时间在加载时被解析为 `time_t` 时间戳。
- **Planner 类**: 核心控制器。
    - `flights`: 使用 `Vector<Flight>` 存储所有航班数据。
    - `adj`: 使用 `Vector<List<int>>` 实现邻接表，存储从每个机场出发的航班索引列表。

##### 算法实现

所有算法均考虑了航班的时间约束（后一程起飞时间必须晚于前一程到达时间）。

1.  **深度优先遍历 (DFS)** (`query_dfs`):
    - 使用递归实现。
    - 维护 `visited` 集合保证每个机场只访问一次。
    - 在每个节点，收集所有满足时间条件的后续航班，按“起飞时间、目标机场ID”排序后依次递归访问。

2.  **广度优先遍历 (BFS)** (`query_bfs`):
    - 使用 `std::queue` 实现。
    - 同样维护 `visited` 集合。
    - 在扩展节点时，收集所有满足时间条件的后续航班，排序后加入队列。

3.  **连通性查询** (`query_connectivity`):
    - 检查是否存在直飞航班。
    - 检查是否存在一次中转的航班组合（A->X, X->B），且满足时间衔接条件。
    - 返回是否连通及一条可行路径。

4.  **最短时间路径** (`query_shortest_path`):
    - 使用 Dijkstra 算法。
    - 优先队列维护状态 `(到达时间, 当前机场)`，优先扩展到达时间最早的状态。
    - 记录 `min_arrival[airport]` 以剪枝（如果再次到达某机场且时间更晚，则跳过）。
    - 最终回溯路径。

5.  **最小费用路径** (`query_minimum_cost_path`):
    - 使用 Dijkstra 算法。
    - 优先队列维护状态 `(累计费用, 当前机场)`，优先扩展费用最低的状态。
    - 由于费用和时间是两个维度，不能简单地根据是否访问过机场剪枝。采用帕累托最优剪枝：如果到达某机场时，费用更高且时间更晚，则该状态被支配，可以剪枝。

6.  **所有路径查询** (`query_all_paths`):
    - 仅限直飞或一次中转。
    - 遍历所有直飞航班。
    - 遍历所有一次中转组合，收集满足时间窗口限制的所有路径。

#### 编译运行

使用 CMake 进行编译：

```bash
cmake -B build
cmake --build build
./build/airplane
```

#### 命令格式

支持以下命令：

1.  **深度优先遍历**:
    ```
    dfs <机场ID> <日期> <时间>
    示例: dfs 48 5/5/2017 12:00
    ```

2.  **广度优先遍历**:
    ```
    bfs <机场ID> <日期> <时间>
    示例: bfs 48 5/5/2017 12:00
    ```

3.  **连通性查询**:
    ```
    connectivity <机场ID1> <机场ID2>
    示例: connectivity 48 50
    ```

4.  **最短时间路径**:
    ```
    shortest <机场ID1> <机场ID2> <起始日期> <起始时间> <结束日期> <结束时间>
    示例: shortest 48 50 5/5/2017 00:00 5/8/2017 23:59
    ```

5.  **最小费用路径**:
    ```
    min_cost <机场ID1> <机场ID2> <起始日期> <起始时间> <结束日期> <结束时间>
    示例: min_cost 48 50 5/5/2017 00:00 5/8/2017 23:59
    ```

6.  **所有路径**:
    ```
    all_paths <机场ID1> <机场ID2> <起始日期> <起始时间> <结束日期> <结束时间>
    示例: all_paths 48 50 5/5/2017 00:00 5/8/2017 23:59
    ```
